# Phase 4 context

Approved scope: AGY-01..05, all prototype agency functionality, SQL persistence, deterministic demo services, unit/real-SQL/browser verification. Phase 3 verified in01818c3, production d1c8174. User authorizes design/implementation choices without routine questions. This context is derived from source and approved requirements, not invented user answers.

## Decisions

- Extend the existing Agency identity; preserve Phase 3 agency/client/relationship IDs and history. Use typed optional draft fields in AgencyOnboarding JSON plus relational state, ownership, user/product/evidence/approval/delivery records. Save incomplete drafts and step1..6 atomically before wizard navigation. Abandon is a recorded terminal draft transition, never deletion.
- Reproduce all six source stages and all options, including GB/NI territory, portal-only correspondence, restricted regulatory permission, volume commitment mode and referral routing. Correct incomplete/broad draft enums before implementation. Source numeric examples are fictional demo rules, not regulatory certification. No six-digit reference alone can count as verified.
- Evidence separates declared form answers, supplied file/attestation and verified check results. Immutable attempts bind to the relevant current input fingerprint and expire where applicable. Activation ignores obsolete verification after a relevant edit. Record FCA/permission, TOBA, PI, financial standing, sanctions/adverse media, ownership, DPA and applicable client-money evidence. Demo providers persist deterministic pass/refer/unavailable outcomes; no real provider calls.
- Minimal agency evidence attachment storage belongs to this phase: bounded PDF/PNG/JPEG/text files, hash/content type/filename/size and SQL bytes, safe authorized attachment download, explicit demo screening state. Do not accept arbitrary URLs/storage paths or fake Document IDs. Phase 9 later integrates the generic document workspace without losing these records.
- The wizard stages broker users as invited identities with one agency and exactly one allowed broker role. No token/delivery is issued while draft. Activation requires a viable staged or active broker administrator; active-agency invitations dispatch immediately. Invite expiry is14days from issue, not draft creation. Resend rotates the token and invalidates previous acceptance; revoke/expiry preserve history. Never activate a user merely because a delivery succeeds.
- Existing internal roles are not broker roles. Add broker-admin/broker-user/broker-readonly with Scope=agency and StaffUser.AgencyId FK. Enforce no mixed role scopes in service and SQL; local authentication/session retrieval derives trusted agency identity from storage, rechecking user/agency state and current roles. No request/header may choose the caller's agency.
- Agency activation, suspension and published commercial changes require independent approval, matching the source countersign/suspension/dual-approval semantics. Agency-admin and system-admin can propose/manage; separately authenticated agency-admin or system-admin can decide another user's proposal. Seed a second fictional agency reviewer for the demo. No self-approval or client-supplied approver IDs. Approval atomically validates the current proposal/base version and applies it; stale proposals must be refreshed/replaced, never silently applied.
- Preserve effective-dated immutable commission/settlement versions. Serialize all scheduling under the agency parent; reject overlapping/conflicting schedules. Product selection is mutable only while draft; active/suspended agency changes go through a terms proposal. Percent inputs become integer basis points. Each published version has complete terms/product rows and approval provenance; no rewrite of future policy/finance snapshots.
- Product access does not grant underwriting authority. Phase 2 product versions are draft definitions without rating; this phase can record a proposed grant to those versions, but activation requires an explicitly approved demo distribution-eligible product definition. Add a labelled eligibility setting/version without pretending the rating product is published or enabling quote/rating endpoints. Phase 5/6 establish real product readiness before business capture/issue.
- The supported product catalog remains Motor Trade Road Risks, Motor Trade Combined and Commercial Combined. The agency detail prototype also mentions Motor Trade Fleet as not enabled; retain an explanatory unavailable entry only if needed for source coverage, with no invented grant or fourth implemented product.
- Invitations and activation notifications use existing durable job/lease/audit patterns with a dedicated agency-notification kind and persistent demo provider receipts. Track queued/processing/demo-delivered/rejected/exhausted independently of invitation acceptance. Protect invitation payloads with the existing persistent Data Protection keys; ordinary lists/receipts/logs never contain raw tokens/passwords. An audited Development-only demo link reveal enables local acceptance walkthrough; no external message is sent.
- The prototype portal is an internal sharing reference. Build /agents/{agencyId}/sharing using the same safe projection services as dedicated authenticated agency-scoped API reads. No separate broker application. Broker local sign-in/acceptance proves trusted scope through real cookies and APIs; internal back-office routes remain internal. Provide only a minimal access/acceptance result page for external identities, not a customer workflow.
- Agency suspension and user deactivation/role changes revoke relevant sessions/stamps atomically. Old cookies and previously successful command keys must not bypass current permissions. Reactivation does not restore old sessions or resurrect revoked invitations. An internal preview is audited and never changes the staff session into a broker identity.
- Persist agency permission requests/grants for the source bordereau-download example, with approve/reject/revoke and no internal role escalation. The grant is visible now but actual bordereau export remains Phase10 and must enforce it there. Broker-admin may manage only its own users; protect the last active administrator and prohibit self-elevation/mixed role grants.
