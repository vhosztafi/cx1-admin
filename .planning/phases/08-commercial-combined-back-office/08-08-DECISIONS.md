# 08-08 implementation decisions

The approved dated exposure design is refined as follows. These are implementation choices under delegated autonomy, not new scope.

- Stable book identity is independent of binder-version IDs. Immutable same-product/provider mappings bind every participating binder version to that book. Exposure headers retain verified term/transaction/version metadata and source hash so whole-book reads do not acquire mutable foreign policy locks.
- A limit publication may explicitly reference SupersedesLimitId for the same book and district/default scope. At E/K, an applicable visible descendant replaces its ancestors only for its own effective interval. Older limits remain applicable outside that interval and before publication knowledge. Multiple competing unsuperseded applicable publications block assessment. This permits legitimate immutable dated changes without editing a historical end date or silently choosing a competing larger limit. District-specific applicable publications take precedence over the default. The default district marker is '*'.
- Exposure selection counts only active policy-term winners, using effective date, known processing cutoff, transaction sequence and slice ordinal. Cancellations have complete empty headers. Multiple positive property locations in one district sum, but the policy count remains distinct; zero amounts do not add an exposed-policy count. Scheduled and expired winners contribute zero at the observed instant.
- Proposed input is a complete replacement timeline for the affected own-policy interval. Known own-policy changes within that interval must be explicitly represented, preventing an omitted future slice from releasing capacity. Every relevant existing/proposed term/version/limit boundary is evaluated. Other-policy contributions are preserved; only touched districts are returned, with aggregates and no foreign identities.
- SQL materializes all location children from the verified header in the same INSERT. This closes the partial-child gap without adding a mutable completion flag; extra, duplicate, changed or removed children are rejected.
- Storage08-08 provides immutable models, source projection/validation and pure aggregate rules. Atomic issue/receipt integration and scoped exposure APIs remain08-09. Verification uses owned isolated SQL fixtures and preserves the live demonstration database.
