# Persistent client identity and agency relationships

All three plan tasks are complete. Staff can create a business identity, edit it with an ETag, reload it, search/filter/page clients and add agency relationships. Actual SQL records supply the client header, relationship table and safe activity. Source layout is retained through the reusable RecordHeader, explicit client routes, original shell and responsive table regions. These changes implement the client identity portion of CLI-01/02; contacts and actual quote/policy navigation retain their downstream acceptance gates.

System-admin/finance receive no implicit party rights. External local login remains denied; synthetic trusted agency contexts exercise actual SQL positive reads and cross-agency/revoked relationship denial. Commands validate bounded typed input, reject unknown/duplicate/null fields, check current scope before replay and check parent ETag inside a row-locked transaction. Mutation, safe activity, audit and original response receipt commit atomically. Parent client tokens advance on identity and relationship changes. Draft relationships do not complete onboarding; suspended/abandoned agencies cannot be newly linked.
