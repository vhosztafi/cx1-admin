# Phase 10 Plan 09: Versioned provider bordereaux

Provider and accounting-period batches now pin the exact posted insurance journals, contractual signed amounts and product/agency mapping used for a bordereau. Every mapping correction, exclusion and validation creates a sealed successor; a valid successor retains the exact spreadsheet-safe CSV bytes and hash.

## What changed

- `FinanceBordereauService.GenerateAsync(ActorContext, Guid providerId, Guid periodId, string key, Guid correlationId, CancellationToken)` holds current internal finance identity and the provider row before idempotency replay. In a serializable transaction it selects journals with `PostedAt <= SourceCutoff`, filters on held posting date within `[AccountingPeriod.StartsOn, EndsOn)`, and saves one pinned member per journal. Legacy null posting dates use the London projection established by 10-02. Each member retains journal/policy/transaction/agency/product-version/terms IDs, posting date/instant, currency, premium, tax, fee, commission, net due and initial export identifiers. A later product mapping change creates a different batch snapshot without rewriting the old one.
- `FinanceBordereauBatch` is a mutable head; `FinanceBordereauVersion` and `FinanceBordereauMember` are append-only. Every version has a source cutoff/hash, member hash, schema version, parent, ordinal, validation result and optional saved CSV bytes/hash. `CorrectAsync`, `ExcludeAsync` and `ValidateAsync` require the current version ID, use the idempotent SQL command boundary, copy the full member set and advance the head only after the child is saved. Corrections accept policy reference, provider product code and agency reference only; they never accept contractual amounts. Exclusions store actor, reason and time. Validation reports all failures for included rows and saves bytes only when there are zero failures.
- `BordereauCsv.Write` fixes column order, UTF-8 and CRLF line endings, RFC-style delimiter/quote/newline quoting, and apostrophe escaping of untrusted text with formula prefixes. Canonical signed decimal fields retain their real sign. `DownloadAsync` rechecks current authority, current draft head, zero-failure validation, saved member hash, saved byte hash and exact regenerated bytes before returning the saved content. Invalid and superseded draft versions cannot download.
- Migration `20260924100259_FinanceBordereauVersions` adds three tables, unique `(VersionId, SourceJournalId)` membership and `(BatchId, Number)` version indexes, source and financial checks, SHA-256 content check, and triggers rejecting member/version update or delete. The source trigger compares initial rows to posted obligations and successor financial fields to pinned parent rows, so later source mapping changes cannot alter contractual amounts. The batch trigger permits only a complete child version as the next head; SQL rollback of the pointer is rejected.
- Runtime endpoints are `POST /api/v1/finance/providers/{providerId}/periods/{periodId}/bordereaux`, `GET /api/v1/finance/providers/{providerId}/bordereaux`, `GET /api/v1/finance/bordereaux/{id}`, `POST /api/v1/finance/bordereaux/{id}/members/{sourceJournalId}/corrections`, `POST .../exclusions`, `POST /api/v1/finance/bordereaux/{id}/validations`, and `GET /api/v1/finance/bordereaux/{id}/versions/{versionId}/download`. All require `finance-bordereau`; writes require CSRF, an idempotency key and, for revisions, strong `If-Match`. Current stored identity and provider existence are checked before detail, export, count or receipt replay. Commands retain safe batch/version identifiers and ETags, never rows or CSV bytes. OpenAPI and generated TypeScript describe the route/shape; the design-only OpenAPI detail placeholder is replaced by the implemented versioned detail contract.
