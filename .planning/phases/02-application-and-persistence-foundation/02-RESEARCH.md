# Foundation research

SQL readiness is verified: `sqlcmd -S .\SQL2022 -E -C` returns 16.0.1200.5 Developer Edition outside the sandbox. Initial sandbox authentication failure was environmental, not an absent server. Use a dedicated database, compatibility level 160, nvarchar(max)+ISJSON checks for snapshot columns. Native Windows integration is the primary local profile; Compose SQL Server 2022 is an alternative.

Use EF Core SQL Server with explicit compatibility and migrations, no EnsureCreated replacement for migration tests. [Microsoft provider documentation](https://learn.microsoft.com/en-us/ef/core/providers/sql-server/) explains provider configuration and warns that EF compatibility does not change database compatibility. Pin EF 10.0.12; keep .NET 10.0.401 SDK via global.json. System-wide SDK changes are unnecessary.

Use ASP.NET cookie authentication backed by SQL session/ticket storage, built-in password hashing and Data Protection keys persisted outside tracked files. Authenticate from real seeded datastore users, validate session/security stamp on each request, and return API 401/403. [Cookie authentication](https://learn.microsoft.com/en-us/aspnet/core/security/authentication/cookie?view=aspnetcore-10.0) documents middleware ordering and API behavior. Apply explicit antiforgery tokens to cookie-authenticated mutations; login obtains an anonymous token first to avoid login CSRF. [Antiforgery guidance](https://learn.microsoft.com/en-us/aspnet/core/security/anti-request-forgery?view=aspnetcore-10.0).

Next App Router on Node 24 is compatible with the documented runtime requirements. Use server-rendered shell with small client islands; a same-origin /api proxy to the .NET service avoids browser CORS and cookie-host mistakes. [Next installation](https://nextjs.org/docs/app/getting-started/installation). Pin Next 16.3.5/React 19.3.0/Tailwind 4.3.3 verified from the package registry. Do not dynamically fetch sensitive user-specific data into shared caches.

Risk controls: SQL migration and runtime tests must fail rather than silently skip when SQL is unavailable. Test session revocation, CSRF, bad credentials, scope and post-restart persistence. Test durable jobs using distinct worker/provider commits and unique keys; a single transaction cannot simulate provider success followed by timeout. Avoid a generic JSON entity store; use bounded foundational SQL tables and add domain tables in owning phases.
