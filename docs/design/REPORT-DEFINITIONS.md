# Report measures and snapshot rules

These six report codes are distinct seeded definitions. A run pins definition version, filter values, UTC as-of time and current authorised record scope in ReportRun. Pagination reads that run's stable ordered row projection; a filter change starts another run. An expired run returns 410 `report-run-expired`. Export refers to the same run or explicitly starts a new one; it must not silently change the numbers between screen and file.

Money measures use exact decimal strings; percentages use numerator/denominator integers with display rounding to two decimal places. A zero denominator produces an absent percentage and a visible “No eligible records” explanation, never 0% or NaN. Excluded records and cancelled/refunded movements are handled according to the definitions below, not by dropping every negative amount. Dates are half-open `[from, to)` in Europe/London; display the chosen effective or processed basis in the title and export metadata.

| Report | Measures and denominator | Rows/drill-down | Default basis |
|---|---|---|---|
| underwriting | Submitted quotes, referred submissions, bound submissions; referral rate = distinct submitted quotes with at least one blocking referral / distinct submitted quotes. Bind rate = bound submitted quotes / submitted quotes. One quote counted once regardless of revision count. Cohort is first submission in period, outcome evaluated at run as-of. | Quote with submitted date, product, agency, latest outcome at run cutoff and referral summary safe for actor. | processed |
| portfolio | Written premium = signed PremiumMovement premium in period; active policy count at `to` minus one tick uses effective/known history at run cutoff and latest applicable term per policy. Earned premium = component premium × overlapping local calendar days / component interval days, rounded per movement; cancellation reversal movements adjust earning only over their linked unearned interval. | Issued transaction/version and policy; no draft risk or support flags. | effective |
| renewal | Eligible expiring terms = terms ending in period excluding cover cancelled before expiry. Renewed = eligible terms with an issued successor by run cutoff; lapsed = explicit lapse; awaiting = remaining. Retention = renewed / eligible. A future successor counts as renewed once issued, with scheduled cover labelled. | Expiring term, successor reference, invitation/acceptance state, expiry and owner. | effective |
| finance | Net written receivable, cash receipts, payments/refunds, outstanding balance, unallocated cash and unreconciled bank variance. Signed journal lines on control accounts govern totals; don't sum invoice and journal amounts twice. Outstanding at cutoff includes allocation reversals and applied credits. | Invoice/credit, receipt, refund and journal with agency and period. | processed |
| agency | Submitted/bound quote cohort measures by agency, signed written premium, broker commission, outstanding debit and overdue debit. Overdue = positive outstanding whose DueOn is before cutoff local date; credits shown separately, not counted as overdue. | Agency totals drill to the same scoped source rows. | processed |
| compliance-exceptions | Open blocking referrals, overdue tasks, exhausted integration jobs, missing/expired agency evidence, pending identity approvals and unreviewed matches. Count unique records at cutoff; overdue uses due instant, evidence expiry local date. No restricted flag category/detail in report; a permitted review-due flag count uses a separately scoped measure. | Typed exception record and action owner; unsafe subjects omitted before counting. | processed |

Filter support: all reports accept date range and relevant product/agency/provider scopes. Unsupported filter combinations return 422 rather than being ignored. Status codes are allowlisted for each report definition. Requested record IDs never expand user access. Sorting is definition-specific with stable UUID tie-breakers. UI can save/favourite a definition+filters without sharing another user's report snapshot.

Implementation verification must reconcile sums and cohort counts against seeded SQL source rows including a renewal, declined quote, multiple revisions/referrals, return-premium MTA, cancellation, receipt reversal, closed period and empty cohort. These definitions are not evidence those queries have been implemented.
